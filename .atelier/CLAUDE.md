# .atelier — design scratch

Generated by atelier — rewritten whenever a command runs, so put nothing of
your own in it.

This is where design exploration happens: a directory per month, one per design
question, a dated round inside that — `2026-07-30-v1` — and a `.tsx` file per
option. `atelier dev` serves them as a gallery with a control panel; the state
the user settles on is written to `saved/<design>.json`.

The date in a round's directory name is what the index groups and sorts by, so
renaming or recreating one moves the exploration to a different day. Everything
that refers to a round — refs, URLs, saved JSON — calls it `v1`, without the
date, and is unaffected.

`proof/` is not part of this. It holds throwaway files that render components
the source tree already has — no study, no round, no date, nothing kept.
**Everything below is about studies and none of it reaches there**;
`proof/CLAUDE.md` has its own rules, and they invert four of these.

## It is scratch, and it is dated

Everything here records what was being considered at a particular moment. It is
not part of the application, and it is deliberately not kept in step with it.

- **Do not refactor old explorations to match the app.** Once the real component
  moves on, the mockup becomes evidence of what things looked like when the
  decision was made. Updating it to match destroys the only copy of that.
- **Duplication between a mockup and the real component is expected.** A design
  that redraws the header in 200 lines is not waiting to be de-duplicated.
- **Do not import the subject; do import its context.** A mockup that imports the
  component it is *redesigning* silently changes whenever that component does,
  which is the same problem arriving more slowly — and you cannot add a knob to
  something you imported. `atelier adopt` brings the subject in as a frozen copy,
  which is precise *and* stays put.

  The thing the subject sits *inside* is the opposite case, and importing it live
  is the point: `atelier inject <target> <host>` renders the real host and swaps
  your design in underneath it. Drift is what you want there — the context
  should be today's context. Adopt the leaf, inject it into the live host, and
  the round holds one copy instead of a tree of them.

  `.atelier/atelier.config.json` is what makes those imports readable: aliases
  and tokens you would never edit in a mockup. Note that its `css` key applies to
  every round here, finished ones included; `alias` does not.

  A host that needs runtime context to render at all — providers, a router —
  gets it the same way. Put the wrapper in one file at the root of this directory
  and let the rounds that need it import it; keep the fixtures in the round,
  because the data is the argument and the plumbing is not. Sharing it is the
  point: a mockup rendering live components inside a provider stack copied
  months ago is the worst of both, since the components move and the copy does
  not.

  **A round imports its wrapper rather than being given one**, which is what keeps
  a frozen round frozen: one that says nothing keeps drawing what it always drew.
  The catalogue is the other case and takes its wrapper from configuration, because
  it is derived from the whole source tree and has nobody to ask.
- **So some rounds are frozen and some are alive, and it matters which.** A
  round that only holds copies and fixtures renders forever. A round that
  reaches into live code — injected, imported live, or mounted through a shared
  wrapper — holds up until the app moves far enough, and then it stops
  rendering. That is the price of it having been accurate on the day it was
  made, which is the only thing that made it worth looking at, so it is a trade
  rather than a defect. Do not go back and repair one. Nothing here will warn
  you either: a round whose imports have rotted still has its old screenshot on
  disk, so the gallery shows a healthy-looking picture of a design that no
  longer runs.
- **Nothing here ships.** When a design is chosen, read its
  `saved/<design>.json` and build the real thing in the actual source tree.

`saved/*.json` is the exception to all of the above: it is the decision itself,
and the one thing meant to travel out of this directory. It is also what a living
round leaves behind once it stops rendering, along with whatever `atelier note`
recorded — which is the reason to write the note while the picture is still on
screen rather than after.

**`.atelier/` is committed by default**, because the mockups are the argument for
how something ended up the way it did, and an argument kept on one person's disk
is an argument nobody can read. What stays out is everything in here that is not
that argument: `.shots/`, `.exports/` and `.cache/` are derived and come back on
demand, `proof/` is a look at existing code and makes no argument, and the
`example-` studies are shipped by the package rather than written here. A repo
that would rather keep the whole directory out of git can put `.atelier/` back in
its `.gitignore`; nothing here will put it back.

`atelier prune` says what is taking up room and is the only thing that removes
any of it. Nothing runs on a timer and nothing goes by age — a round's value does
not decay on a schedule, and the ones worth keeping longest are the ones some
shipped comment points at.
